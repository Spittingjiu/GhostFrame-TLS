# GhostFrame-TLS (GFT) 未来演进与架构演进建议书

**呈送**：技术经理 `Argon4`  
**编写人**：全栈系统与网络研发工程师  
**版本**：v1.0 (2026-11)

---

## 一、当前 v1 架构优势总结

GhostFrame-TLS (GFT) Pro 在当前架构下已取得对抗深度包检测（DPI）与主动探测（Active Probing）的核心竞争优势：
1. **0-RTT 协议握手**：将目标地址与初始请求直接捎带在首个加密帧中，彻底消除传统 SOCKS5/Shadowsocks 带来的二次往返时延。
2. **纯粹伪装与无损回落**：基于 `RewindConn` 实现同一端口上的协议分流，对外表现为标准的 Nginx 英文技术博客，无法通过重放或端口扫描打上代理指纹。
3. **免域名证书 Pinning**：客户端强制校验自签名证书的 SHA-256 指纹，彻底免疫针对公共 CA 的中间人劫持（MITM），同时免除因域名被污染而导致的不可用。

## 二、下一代 GFT v2 演进建议

为了在未来更复杂、多变的对抗环境中保持持续可用性与极佳体验，建议团队在以下方向进行迭代：

### 1. 引入 QUIC / HTTP/3 (UDP) 双栈通道支持
- **现状**：当前基于 TCP + TLS 1.3，在遭遇高丢包率或跨国骨干网拥塞时，TCP 队头阻塞（Head-of-Line Blocking）可能导致部分多路复用流短暂卡顿。
- **演进方案**：
  - 设计 **GhostFrame-QUIC (GFQ)** 协议分支，采用 UDP 封装并伪装为 WebTransport 或 HTTP/3 流量。
  - 在客户端实现 TCP/UDP 竞速握手（Happy Eyeballs），优先使用 UDP QUIC 传输；若检测到当地运营商对 UDP 进行 QoS 限速或阻断，毫秒级无缝降级回退至 TCP TLS 1.3。

### 2. 动态爬取与实时反代诱饵（Dynamic Decoy Mirroring）
- **现状**：当前服务端内嵌了高质量静态英文技术博客（*Quiet Compiler*），虽足以欺骗绝大多数扫描器，但长期开放可能被机器学习爬虫提取指纹特征。
- **演进方案**：
  - 在服务端引入动态诱饵爬取与透明反向代理引擎。
  - 定期随机同步国际知名极客博客（如 LLVM Weekly、Rust RFC 讨论站、ACM 论文摘要站）的 HTML 与静态资源。
  - 当触发 Fallback 时，实时代理真实的海外源站内容，使得探测端无论是审查文本更新、页面哈希还是 HTTP/2 特征，均与真实全球知名技术站点 100% 一致。

### 3. 双棘轮密钥自动滚转（Zero-Touch Key Ratchet）
- **现状**：当前采用预共享密钥（PSK）+ 时间戳 HMAC 校验。若管理员在线更新 PSK，客户端需同步热加载或扫码更新。
- **演进方案**：
  - 在 Knock 握手成功后，利用 X25519 临时密钥协商（ECDH）生成临时的会话派生密钥（Session Keys）。
  - 引入类似 Signal 的双棘轮算法（Double Ratchet），每个多路复用数据帧均在上一帧的基础上衍生单向 Hash 棘轮步进，实现完美前向安全（PFS），即便历史密钥泄露也无法解密此前的数据流。

### 4. 虚拟网卡 TUN 模式（Transparent Kernel-level Proxy）
- **现状**：客户端当前采用 SOCKS5 (`10808`) + HTTP (`10809`) 并通过修改 Windows 注册表联动系统代理。部分不走系统代理的特定软件（如游戏进程、部分命令行工具）需要单独配置。
- **演进方案**：
  - 在客户端集成 `wintun.dll`（Windows）及 `utun`（macOS/Linux）驱动。
  - 支持一键开启 **TUN 虚拟网卡模式**，通过轻量级 gVisor / lwIP 网络栈将整机所有 TCP/UDP 流量全透明接管，提供媲美专业 VPN 的全网零配置穿透体验。

### 5. 多节点聚合与智能路由（Multipath Bonding）
- **现状**：客户端当前主要连接单台日本东京 VPS。
- **演进方案**：
  - 支持多节点链路聚合（Multipath Bonding），将日本、新加坡、美国等多台 VPS 的带宽与可用性统一调度。
  - 根据目标域名的全球地理位置，实现智能分流（如日韩流量走东京节点、欧美流量走西雅图节点、中国大陆直连），最大化降低端到端访问延迟。
